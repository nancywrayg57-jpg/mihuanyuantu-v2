# 蜜獾原图 v2 HTML 原型

这是一个离线HTML交互原型，入口为 [`index.html`](./index.html)。四种图片获取方式统一归入“图片资源”，获取成功只入库；“批量原图”仅从资源库选择图片进行处理。资源、任务、删除与持久化均为本地模拟，不接入真实OSS、后端、模型或支付服务。

## Gemini Vision 检测与自动重做（2026-11-02）

生产合同见 [Gemini Vision 检测与自动重做方案](../docs/蜜獾原图-v2-Gemini-Vision检测与自动重做方案-v1.0.md) 与 [继续使用 Gemini Vision ADR](../docs/architecture_decisions/蜜獾原图-v2-继续使用Gemini-Vision最终检测-2026-11-02.md)。Check_Aimage / Synthbuster 试验产物已清出仓库。

- 系统管理 → 自动重做：用户可开关，默认关闭；阈值 0—100（默认 70）；追加 1—5 次（默认 1）。提交处理任务时写入配置快照。
- 通过标准为 Gemini 五维总分 ≥75 且 `passed=true`。`total_score < 阈值` 触发自动重做，等于阈值不触发；该条件独立于 75 基线。
- 新处理任务展示五维报告、总分、判定与自动重做原因。技术异常、缺分、质量失败不自动循环。检测重试最多 2 次，不增加处理轮次、不另计费。
- 每张成功图片 10 积分，自动轮次不叠加；未通过可预览下载但不收费。若旧数据仍带 Check_Aimage 报告，只显示「历史研究夹具，已停用」，不渲染分数。
- 模型 API 的「最终检测」用途恢复为 Gemini 渠道，可与预审/生图/提示词优化按用途隔离配置。
- 主脚本依赖本地 `check-policy.js`（导出 `GeminiRedoPolicy`）。改完 `prototype.js` 后执行 `node prototype/sync-inline.js`，使 `index.html` 内嵌脚本与主脚本一致。夹具不是真实 Gemini 测量。
- 2026-10-28 Check 原型口径已随试验产物删除，不再约束现行页面。

## 使用

直接双击 `index.html` 即可打开；如需观察 `localStorage` 或避免浏览器的本地文件限制，可在本目录启动任意静态服务器后访问入口。首次打开进入账号入口，可切换商家、技术客服和平台管理员角色。改完 `prototype.js` 后执行 `node prototype/sync-inline.js`。

推荐走查顺序：

1. 侧栏顺序为“工作台 → 图片资源 → 批量原图 → 任务详情 → 设备预设 → AI 提示词模板 → 积分与充值 → 工单管理 → 用户管理 → 系统日志 → 系统管理”，按角色隐藏入口。管理员/技术客服隐藏积分与充值；设备预设仅平台管理员；用户管理和系统日志对平台管理员与技术客服可见；消息中心仍为顶栏铃铛。
2. 商家/客服工作台只有四张概览卡（可用积分、进行中任务、本月已完成、未读消息），没有「一条任务链」横幅。管理员工作台只看运营指标。
3. 在“图片资源”点击“添加图片”，选择文生图、图生图、本地上传或 URL 导入。文生图/图生图保留生成表单、提示词模板选用、提示词优化和三阶段进度；完成后可预览/批量下载，主后续动作为「前往图片资源」，不自动进入五层。图生图可选已有资源或临时参考图，临时参考图不入库。
4. 资源列表是表格（缩略图 + 拼接文件名），每页 20 张，可按来源筛选。文件名按 name / seller / sku / asn / price / website / url 拼接；sku 可空并生成 16 位内部编号。本地上传单次最多 20 张；URL/JSON 导入单次最多 100 条（逐行 URL、粘贴 JSON 或上传 JSON 文件），只校验文本，不访问外部地址。勾选 1—10 张「去处理」，或在「批量原图」弹窗选图后选一套启用设备预设并开始。
5. “任务详情”默认「图片处理任务」标签，其次「生图任务」，各每页 10 条，按提交账号与租户隔离。处理详情含按张账务、处理轮次时间线、复制与主动重处理；生图详情只保留预览、批量下载、逐张查看与按张计费，不含复制/重处理/轮次时间线。处理结果不回流资源库。
6. 在“设备预设”以平台管理员查看 405 条旧版记录；新建/编辑弹窗选项卡为基本信息、拍摄参数、EXIF增强、版权信息、AI提示词。GPS 只在预设中配置（不写入 / 固定坐标 / 按场景随机）；处理提交时继承快照。
7. 在“AI 提示词模板”维护平台/租户模板；选用不扣积分。在“积分与充值”提交人工充值：档位为 100/300/500/1,000/3,000 元，对应 1,000 / 3,150 / 5,500 / 11,500 / 36,000 积分。
8. “系统管理”：商家仅自动重做；平台管理员另有模型 API。用户管理与系统日志为管理员/技术客服一级菜单。工单与消息按账号隔离；技术客服处理授权范围工单，平台管理员处理全平台工单。

## 角色与菜单范围

| 角色 | 菜单/能力 | 数据范围 |
| --- | --- | --- |
| 商家 | 工作台、图片资源、批量原图、任务详情、AI 提示词模板、系统管理（仅自动重做）、积分与充值、顶栏消息 | 本账号资源与任务；公共启用预设在处理表单调用 |
| 技术客服 | 工作台、图片资源、批量原图、任务详情、AI 提示词模板、消息、工单、用户管理、系统日志、系统管理；隐藏积分与设备目录 | 本账号历史隔离；授权工单；可操作用户并写系统日志；不管理平台模型或公共预设 |
| 平台管理员 | 设备预设、模型 API、用户管理、系统日志、工作台运营指标、全平台工单；隐藏积分与充值 | 本账号历史隔离；全平台配置与审计；工作台不显示商家四张概览卡 |

## 设备预设

平台管理员页面载入 `输入材料/旧版可复用模块/02_设备参数/线上预设_脱敏原始.json` 的 405 条唯一预设。旧版记录默认未启用/待复核，管理员可逐条启用或停用。新建/编辑弹窗选项卡为基本信息、拍摄参数、EXIF增强、版权信息、AI提示词；GPS 模式与坐标/随机场景在预设内配置，不写入时隐藏坐标。批量原图只列出状态为「启用」的预设。IP-GEO 不纳入表单。

## 任务、账务、消息与工单

- 处理提交前按拟处理张数 × 10 冻结；逐张结算，通过检测扣 10；自动轮次不叠加；未通过可下载不收费。前置失败不冻结对应张。
- 生图不预冻；提交时校验可用余额 ≥ 生成数量 × 10；成功入库后按张扣 10。提示词优化成功 1 积分/次。
- 演示种子按张展示：例如 4 张成功消费 40，2 张自动重做仍消费 20。
- 任务详情状态覆盖预审未通过、图片已锁定、账号冻结、技术异常、自动重做、检测失败、已过期和已删除；处理详情展示 Gemini 五维报告与按张账务。
- 文生图/图生图只入库；上传和 URL 导入也只入库。处理阶段为输入校验、预审、技术处理、结果检测、结果交付。关页后续跑，刷新按本地快照恢复。
- 批量下载不生成 ZIP；优先目录写入，否则浏览器逐文件下载。
- 消息与工单按账号隔离。冻结账号可看历史，解冻后才能新建获取/处理任务。
- 提示词优化、模型、下载、支付、地理编码和 URL 导入均为演示替身；模型 Key 只显示掩码。第一版不演示 10 Key 轮询。

## GPS 配置

不再提供独立的「GPS 配置 / GPS 预设」页面；仅在设备预设弹窗中配置。批量原图提交时由所选预设带入 GPS 快照。地理编码和地图均为 mock。

## 图片资源生命周期（2026-10-28）

- 原图长期保留、可重复使用；资源表格展示文件名与来源，存在任一运行中任务时优先显示处理中。
- 单次处理最多10张并使用同一套启用设备预设；参数预览默认折叠，GPS随提交时的设备快照保存。
- 下载、删除可跨页选择，不套用处理的10张限制；批量下载避免同名文件覆盖，不生成ZIP。
- 删除前确认；所选图片中存在任一运行任务时整体阻止删除。原型只写删除标记，不操作OSS。
- 删除后移出资源列表，关联生图历史中的原图不可预览/下载；历史记录和既有处理结果保留，处理输出不会重新入库。
- 本地文件只读取名称、大小、类型等元数据，URL不请求外部服务；所有预览及下载内容仍为固定原型图片，不代表真实上传、解码或生图。

## 用户管理与系统日志（2026-10-28）

- 创建账号、积分、权限管理、启停用、重置密码和删除均使用重新挂载的操作窗口；每个目标动作携带账号 ID 和租户范围。
- 积分只接受正整数额度，可增加或减少；余额不足或输入小数时拒绝提交。调整填写原因，当前示例商家的余额与积分流水联动；其他租户的调整流水不展示给该商家。
- 权限管理可选择角色并调整功能权限，以“保存权限”提交；不再提供行内角色选择和“保存角色”。
- 重置密码要求两次输入一致；密码仅用于窗口校验，不保存明文到本地状态或日志。删除须输入目标登录账号确认；当前管理员的权限、启停和删除受保护。
- 系统日志每页 20 条，记录平台管理员或技术客服对用户账号的成功变更：创建、增加/减少积分、权限变更、启用/停用、重置密码、删除。记录操作人（含账号 ID）、时间、目标账号、租户、变更前后值、原因和结果；不记录本轮原型修改、系统更新或模型配置操作。
- 本轮使用本地 `vendor/decimal.js`（10.6.0，保留 MIT 许可）计算整数积分，无远程运行依赖。

## 任务详情账号隔离与客服用户入口（2026-10-29）

- 任务详情与消息中心一致，按 `messageRecipient.recipientId + tenantId` 隔离；工作台最近历史、详情与结果操作同一范围。旧无归属历史仅迁移给示例商家。
- 技术客服侧栏开放用户管理与系统日志；模型 API 与设备预设仍仅平台管理员。
- 历史增量 ADR 已归档：`docs/archive/2026-10-29-prototype-history-isolation-support-user-admin.md`。现行入口见 [`docs/README.md`](../docs/README.md)。

本原型跳过真实注册、密码认证、验证码、会话有效期和登录失败锁定；创建账号/重置密码仅演示管理交互，入口不验证真实账号。上述条目不代表后端认证或真实用户管理 API 已经实现。

## 验证边界

图片资源拆分、消息隔离与账号历史隔离曾做过定向浏览器检查；当时结果文件不作为现行合同。目录/文件选择与写入使用浏览器替身；未重验原生系统选择器和 file:// 直开。这些未验证项不计入通过数。现行产品口径以 PRD document_version 2.6 与 Gemini 方案为准。
