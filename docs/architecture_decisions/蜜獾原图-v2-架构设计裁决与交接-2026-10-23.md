## 3. 核心架构落点

- 模块化单体 API + 独立图片 worker + 独立消息 / 维护进程；业务包 code=realphotos、表名前缀 cap_realphotos_、独立 Alembic 版本表。
- 底座 task_queue / worker_runtime 可复用；样例没有持久业务表，图片任务表、消费者与实际并发证明必须新增。
- PostgreSQL 持久队列与 version 资金并发控制，首版不采购 Redis、独立队列中间件和负载均衡。
- 底座原 Decimal 账本不能直接视为整数账本；本项目使用一个整数业务账本，并在后端阻止绕过它的旧积分消费入口。
- 通常任务冻结、ND-025 复制免再次冻结、ND-019 主动重处理独立冻结三条路径分别设计。复制门闩期间充值 / 正向入账和已冻结任务结算继续，迟到 worker 不得补扣。
- 五层按 PRD 顺序；旧版色差桩、EXIF 静默回退、错误 APEX、resize 和 60%–80% 体积目标不迁入。处理后统一 sRGB JPEG，最终实际字节下限和完整参数回读需小样验证。
- OSS 私有资产经网关逐次校验租户、用途、到期与删除；ZIP 不延长成员结果访问，图片副本清理覆盖版本、复制、工作盘与下载包。
- 推荐 Ubuntu 24.04 LTS / systemd / Nginx，Python 3.12 / Node.js 22 / pnpm 10 / PostgreSQL 16 为兼容目标；具体补丁和云 SKU 仍需核验，不宣称安装或实测完成。

本次设计细节以主文档 AD-001～AD-012 为索引，属于推荐实施设计；用户明确确认项以上节为准。官方稳定 Release 关系、完整提交固定及原有 ND-011/ND-012 供应商验证继续落实，不新增 ND-032 已排除的专项审查门禁。
