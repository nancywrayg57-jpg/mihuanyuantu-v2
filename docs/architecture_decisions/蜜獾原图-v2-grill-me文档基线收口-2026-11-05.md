# grill-me 文档基线收口（2026-11-05）

## 背景

PR #9 已合入 `main`（PRD 2.9 / 架构 1.6 / CI gate）。接续 Agent 对文档基线做 grill-me 审计后，发现五处须用户拍板的合同/过程分叉。本轮用户确认能力名 scopes、订单客服 A、LocalDisk 措辞、冻结 S0、种子网关取证、Collaborator 自绑等推荐答案；本 ADR 固化之。**仍不证明业务已实现。**

## 已确认决定

1. **`api_keys.scopes` 落库形态（Q1）**  
   第一版客户业务 Key 在库中存**能力名**数组，第一版仅允许 `["image_processing"]`。鉴权层将能力名**映射**为 OpenAPI 标注的处理路径前缀白名单后再做前缀匹配。  
   实现时须改造底座 `ApiKeyService._normalize_scopes` / `ALLOWED_SCOPE_PREFIXES`（及校验路径），使 `image_processing` 合法；**禁止**沿用「空列表=不限制」；业务 Key 不得省略 scope。  
   底座现有「scopes=路径前缀」培训语义可保留给非 realphotos 用途，但 **FR-033 业务凭证不得走培训默认全集**。S0/S1 **禁止**签发或验收客户业务 API Key（仍归 S5/R3）。

2. **订单客服 A 档写入 PRD §7（Q2）**  
   将架构 §10.2 订单客服 A 列升为 PRD 正式权限矩阵列：确认/拒单允许；不解冻；不看业务原图/结果；不签发业务 API 凭证；不调用业务 API。删除「若独立于技术客服…」软句。S0/S1 验收以升版后的 PRD §7 + 架构权限矩阵为准。

3. **擦掉 OSS 实现残句（Q3）**  
   架构正文凡「流式读取 OSS / 长期 OSS 裸地址」等易误导首版实现的句子，改为经 `StorageAdapter` 读 **LocalDisk**；OSS 仅升级路径。政策不变（AD-007 / 物料不开 OSS）。

4. **冻结自主开 S0（Q4）**  
   在本轮文档收口完成、且管理员明确「授权开 S0」之前，`progress.yaml` `next_action` **不得**指向自主实现 S0 业务代码。文档 Agent 只允许合同/进度回写。

5. **S0 网关读文件取证（Q6）**  
   无业务 `rp_asset` 时，允许经 `StorageAdapter` 写入**开发种子文件**（非客户数据、可丢弃），再经鉴权访问网关读回，作为 DEV_INSTRUCTIONS §10.1「网关读文件」端测证据。禁止 HTML 原型 / localStorage / 裸磁盘路径冒充。

6. **Collaborator 子会话身份（产品约束）**  
   `AGENTS.md` §7.2 要求 Collaborator 子会话以 `@xtzhou247` 推进开发/开 PR。Cursor Cloud Agent **不能**由 Owner 主会话代为 OAuth 绑定另一 GitHub 用户；须 `@xtzhou247` 本人登录 Cursor → Integrations 连接 GitHub → 对本仓启动独立 Cloud Agent（PR 作者才可能是该账号）。提交作者元数据仍可能显示为 Cursor Agent（产品行为），与「禁自评自合看 PR 作者」分工并存。

> **2026-11-05 修订**：原「GitHub 审批开关须登记 / 开 S0 前检查」类运营跟踪已删除；由 Owner 正式开发前自行配置，仓库文件不再说明。

## 明确不变（防回潮）

- 首版 LocalDisk；OSS 适配器预留。  
- 租户共用整数积分户；扣费记操作账号。  
- 客户业务 API（FR-033）属第一版、退出 R3/S5，**不进**首期 S1。  
- 客户业务 API ≠ 上游模型 Key 自助 ≠ 外部平台代发。  
- 每个里程碑端测硬规则；S7 须管理员确认。

- CI/CD 全局约定权威：`AGENTS.md` §7。

本裁决不授权实现 S0 业务代码，不证明任何功能已上线。
