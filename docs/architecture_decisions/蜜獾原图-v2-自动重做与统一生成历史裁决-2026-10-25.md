# 蜜獾原图 v2 自动重做与统一生成历史裁决

> **2026-11-02 正文已按 PRD 2.5 改写。** 阈值/次数/触发条件仍沿用 2026-10-25 裁决；计费改为按张、导航改为「任务详情」、自动重做只作用于图片处理任务。第 4 节保留当时文档同步记录。

## 1. 裁决结果

本 ADR 对应 `ND-036`（自动重做）和 `ND-037`（任务详情），并与现行 PRD `FR-026/FR-027`、`AC-018/AC-019` 对齐。

自动重做只作用于**图片处理任务**（资源入库后再提交的五层 + Gemini 检测）。生图成功只入库，不自动进入五层，因此不跑自动重做。

- 用户可自定义最终检测分数阈值，默认 70 分；开关默认关闭。
- 开启后默认追加 1 次，允许设置 1—5 次，次数不含首次处理。
- 触发条件为有可解析的检测总分且 `total_score < threshold`，等于阈值不触发。该条件独立于检测通过基线 `total_score >=75 && passed=true`，所以阈值高于 75 时，已通过基线但低于用户阈值的结果仍可进入下一轮。
- 自动轮次以上一轮有效处理结果为输入，只重跑五层处理和最终检测；不重新调用文生图/图生图，不覆盖既有结果、报告或尝试。
- 处理任务可混选上传、外部导入、文生图、图生图入库的资源。技术异常、缺少分数、无有效结果和前置校验失败不进入自动循环。
- **按张计费：** 该张最多消费一次 10 积分；任一轮通过且有有效结果时对该张幂等结算 10；该张全部轮次未通过则免费。一批 N 张通过消费 `N × 10`。重复调度、迟到回调和进程重启不得重复创建轮次、消费或释放。

独立“检测结果”页面和导航入口移除。一级菜单为「任务详情」：默认「图片处理任务」标签，其次「生图任务」；支持来源筛选、分页和轮次展开；按账号 + 租户隔离。五维分数、总分、判定、未通过原因和每轮结果保存在处理任务详情中。检测查询作为详情子资源保留，不作为独立页面。

## 2. 旧版参考

旧版线上设置页存在「自动重做配置」（启用开关、保存及本地保存提示），URL 为 `https://realphotos.zennolab.cloud/settings`。默认值与边界以当时源码为准：默认关闭、`maxCount=1`、`scoreThreshold=70`，次数 1—5、阈值 0—100；触发为分数低于阈值且未达次数，下一轮使用上一结果。旧版为浏览器状态驱动，不能直接作为 v2 后台执行合同。旧版同时注册 `/history` 与 `/detection`；v2 移除独立检测页。`generation.reprocess` 会重置旧记录；v2 保留手动重处理边界但不覆盖历史。Schema 存在 `autoReprocessCount`；v2 改为链/轮次持久化模型。

## 3. v2 实施口径

1. `auto_reprocess_setting` 按租户保存开关、阈值、追加次数、版本和操作者；提交**处理任务**时写入快照，后续设置变更不追溯修改在途任务。
2. 处理侧以每张图片为计费与自动重做单位；`image_task` 以处理批次 + 资源 + `round_no` 唯一，自动轮次保存 `source_task_id`、输入/输出资产和检测报告。生图任务写入 `generation_task`，不创建处理链。
3. `AUTO_REPROCESS_PENDING` 是显式内部状态；调度器使用事务、租约和唯一键创建下一轮，自动重做不是 SDK 重试。技术失败继续使用原任务的手动重试上限，不增加自动次数。
4. 账本按张使用唯一消费键。该张首次或任一自动轮次通过时消费 10；后续轮次不重复收费；该张全部未通过才释放其处理预留。处理任务提交前按拟处理张数冻结。独立手动 `processing.reprocess` 仍是新处理任务，按通常冻结和计费。生图不预冻，成功入库后按张扣 10。
5. 任务详情按 `task_type=processing|generation` 查询，处理列表 `origin_kind` 支持四类筛选；检测报告为处理轮次详情子资源。所有查询带 `tenant_id` + 接收账号，不以主键单独访问。
