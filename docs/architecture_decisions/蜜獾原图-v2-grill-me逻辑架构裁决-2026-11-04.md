# grill-me 逻辑架构裁决（2026-11-04）

## 背景

独立审计发现：架构「阿里云 OSS」与生产物料「不开 OSS / LocalDisk」分叉；PRD「无共享钱包产品化」与架构「租户唯一积分户」措辞冲突；§13.1 MVP 过胖。经 grill-me 多轮确认后固化下列决定。微决策（夹具注入、双账号并发冒烟、开发验证码）一并认可。

## 已确认决定

1. **存储**：首版 LocalDisk 默认；OSS 仅存储适配器预留。以物料收紧架构 AD-007。
2. **积分**：租户共用余额；PRD 改写「无共享钱包」为「无席位订阅，同租户共用积分户」。
3. **第一刀**：上传→单张处理→检测夹具→按张账本→下载（见 `docs/mihuanyuantu-v2/`）。
4. **订单客服**：正式开发前补 A 档（RBAC + 最小确认/拒单）；完整运营壳后置。
5. **生产红线**：ND-011 与真五层之 ND-020/021 无归档证据 → 禁止生产收费与对外检测承诺。
6. **第一刀真假边界**：硬校验真；预审桩；五层假桩但须 sRGB JPG + 快照字段；Gemini 规则夹具；账本/状态机/落库 worker 真。
7. **真五层**：独立算法证据切片（生图/运营前），须过 ND-020/021 小样。
8. **角色**：第一刀必验商家×2、订单客服、管理员；技术客服延后。
9. **隔离**：同租户双账号证明共用积分 + 账号隔离；另需第二租户证明跨租户拒绝。
10. **运行环境**：第一刀仅开发机验收；禁止未过门禁构建上 `exif-demo` 对外收费服务。

## 明确不计第一刀退出（防回潮）

文生图/图生图、提示词优化、URL 真导入、405 预设运营、真预审/冻号解冻、真五层、真 Gemini、自动重做/重处理、混合批次 2–10、技术客服台、ZIP、OSS、扫码支付、客户业务 API、运营大盘。

> **范围修订（2026-11-05 / PRD 2.9 / 架构 1.5→1.6）**：上表「客户业务 API」仍**不计首期（S1）退出**；但已纳入**第一版产品范围**（FR-033 / AC-024：`X-API-Key` + scope=`image_processing` + OpenAPI/Swagger；复用 `api_keys`；退出见 R3/S5）。仍禁止客户自建上游模型 Key 与外部平台代发。架构 **1.6** 另补首期表裁剪、业务流转（先冻后队）、可执行 RBAC 与双 Token。本 ADR 正文历史用词「第一刀」= 现行「首期 S1」；历史「第一版不做客户 API」口径以 PRD 2.9 为准被覆盖。
>
> **再修订（2026-11-05 收口 ADR）**：现行合同为 PRD **2.10** / 架构 **1.7**（能力名 scopes、§7 订单客服 A、LocalDisk 措辞消歧、S0 编码冻结、禁自评自合门禁条件）。细节见 [收口 ADR](蜜獾原图-v2-grill-me文档基线收口-2026-11-05.md)。
