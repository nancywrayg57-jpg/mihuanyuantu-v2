## 0. 一句话目标

先吃透现有 Gemini 检测方案，再联网找**可替代、低成本**的检测能力（优先 GitHub 开源与免费/低价方案），最后用**四组图片、三轮处理**做实测：

- **未处理图**：检测结果必须与文件名的已分类标签一致，用来证明检测器本身靠谱；
- **处理后的图**：不论原图来自 AI 还是实拍，都要被判为**物理实拍**；
- **三轮中每一轮**的未通过率都 **< 5%**。

> 本版与前版的差异：v1.0 只有"读方案 + 调研"，缺"跑测试"这一关键闭环；v1.1 按 Q1–Q9 的答复重写了指标口径、门禁规则与选型权重。

## 1. 背景

1. 蜜獾原图 v2 的验收口径目前绑定 Gemini Vision（第 6 层 AI 检测验证）：`score ≥ 75 且 passed = true` 视为通过。
2. 该口径存在四类风险：**成本随调用量线性上升**、**模型升级导致判定漂移（RK-01）**、**地区可达性与账号额度限制**、**单一供应商锁定**。
3. 因此需要寻找替代或交叉验证的检测能力，并回答一个更关键的问题：**换成别的检测器后，处理后的图片还能不能稳定被判为"物理实拍"**。
4. 该问题只能用真实样本来回答——现有三轮处理产物（r1/r2/r3，共 594 张）已经就绪，可直接进入测试。

## 2. 目标与非目标

### 2.1 目标

| 编号 | 目标 | 成功判据 |
| --- | --- | --- |
| O1 | 固化现有 Gemini 检测能力基线 | 产出"检测契约基线卡"：输入、五维、阈值、失败语义、成本、延迟 |
| O2 | 找到可替代/可交叉验证的检测方案 | 调研报告覆盖 ≥ 8 个候选，含 **仓库链接、部署成本、适用场景、与原 Gemini 差异、风险点**，并给出 Top3 推荐 |
| O3 | 验证"未处理图判得准" | 原图误判率（判定 ≠ 文件名标签）达到门禁值，证明检测器有判别力 |
| O4 | 验证"处理后都是物理实拍" | **每一轮**处理后图片判为 `physical_device` 的比例 ≥ 95%，即每轮未通过率 < 5%，三轮各自达标 |

### 2.2 非目标（明确不做）

- 不改动图片处理流水线本身（像素物理化、频域扰动、指纹破坏、EXIF 写入等）。
- 不做 TikTok / 小红书 / 微信等平台的**真实上传验收**，也不承诺任何平台侧通过率。
- 不把 Gemini 分数当作"真实拍摄证明"或"平台合规依据"。
- 不在本工单内完成生产环境替换上线（替换决策放到阶段 D 结论之后）。
- **不复跑 Gemini 基线**（Q8）：不产生 Gemini 调用费用，差异分析以文档与历史记录为准。

### 2.3 总成功判据

> **O4 达标 = 第 1、2、3 轮各自的未通过率均 < 5%，且检测器有效性门禁通过，uncertain 率 ≤ 5%，全部样本有可追溯结果、无静默丢弃。**

### 3.2 现有 Gemini 检测契约（基线卡初稿）

| 项 | 现状 | 替代方案必须对齐的点 |
| --- | --- | --- |
| 位置 | 第 6 层 AI 检测验证（`exifVerifier.ts`） | 是否同样作为独立后置环节 |

| 输出 | `passed`、`score`(0–100)、`confidence`、五维分、`conclusion`、`suggestions` | 输出能否映射为统一判定 |
| 五维 | 噪点颗粒、景深焦外、光线曝光、色彩真实、整体真实感 | 维度不可比时如何对齐 |
| 通过口径 | `score ≥ 75` 且 `passed = true` | 阈值是否可配、误判方向是否一致 |
| 失败语义 | 异常**不得**写 0 分伪装低分，必须记技术失败（LD-19 / RG-05） | 技术失败要单独统计 |
| 已知局限 | 主观评分非来源鉴定；模型漂移；预设文本会影响判定（RK-12） | 需在报告中披露 |

> 关键提醒：原 Gemini 提示词把**预设 EXIF 文本**一起喂给模型。若替代方案只看像素，二者**不是同一件事**，不能直接比较。测试必须把"是否提供元数据"作为固定变量分别跑，并在报告里注明当前用的是哪一种。

**技术路线（每类至少查 2 个候选）：**

1. **元数据 / EXIF 规则引擎**——成本≈0，但本项目处理的正是元数据，**单靠它没有验证意义**，只能作为辅助信号。
2. **频域 / 指纹类**（GAN 指纹、周期性峰值检测）——与本项目"频域扰动"直接对抗，是最该测的一类。
3. **监督式分类器**（CNN/ViT，在真实 vs 生成数据集上训练）——通用性好，但跨生成器泛化弱。
4. **生成模型重建误差类**（扩散重建、DIRE 思路）——对扩散模型有效，算力开销大。
5. **多模态大模型零样本**（Qwen-VL、InternVL、GLM-4V、豆包视觉等国内可及模型）——最接近 Gemini 的"可解释 + 零样本"路线，是替代首选方向，且多为低价 API。
6. **商用检测 API**——看免费额度与单价，作为外部交叉验证。

### 6.2 对齐规则

1. 以**文件名 stem** 对齐：处理图去掉 `_legacy_20261029_exif` / `_legacy_r2_20261031` / `_legacy_r3_20261031` 后缀即原图名。

4. 原图与处理图分别计算 sha256，防止拿错文件。

### 6.3 判定口径

| 检测器输出 | 统一映射 | 对原图 | 对处理图 |
| --- | --- | --- | --- |
| `physical_device` / `passed=true` / 概率 < 阈值 | 物理实拍 | 与标签"实拍"一致则对 | ✅ 通过 |
| `ai_generated` / `passed=false` / 概率 ≥ 阈值 | AI 生成 | 与标签"实拍"不一致则错 | ❌ 未通过 |
| `uncertain` | 不确定 | 单列，不判对错 | ⚪ 不计入（Q3），单列比例 |
| 超时 / 报错 / 空响应 | 技术失败 | 单列 | ⚪ 不计入分母；失败率 > 2% 该轮重跑 |

### 6.4 指标定义

#### 指标 A：原图误判率（检测器可靠性，对应 Q1）

对 `测试图` 的 198 张（每 stem 一张；5 个无产物 png 已排除）：

| 字段 | 定义 |
| --- | --- |
| `A_ai` | 未处理 AI 图被判为 `physical_device` 的比例（漏检率） |
| `A_real` | 未处理实拍图（含截屏）被判为 `ai_generated` 的比例（误报率） |
| `A_total` | 未处理图判定与文件名标签不符的比例 |

#### 指标 B：处理未通过率（主验收，对应 Q2/Q3）

对每一轮的处理图（198 张）：

```
B_round = 判为 ai_generated 的张数 ÷ (198 − uncertain 张数 − 技术失败张数)
```

- **B_总**（不论原图来源）：所有处理图都应判为物理实拍。
- **B_AI 来源 / B_实拍来源**：拆分参考，用于定位问题（不单独设阈值）。
- **要求：第 1、2、3 轮各自的 B_round 都 < 5%**，三轮独立判定，不取平均。
- 5% × 198 ≈ 9.9，即**每轮最多 9 张未通过**。

#### 指标 C：uncertain 率（Q3 的配套约束）

`uncertain` 不计入未通过率，但必须单独报告：

```
C_round = uncertain 张数 ÷ 该轮有效处理图数
```

- **C_round 建议 ≤ 5%**；超过则说明该检测器"不敢判"，本轮结论不成立，需按最坏情况（uncertain 计入未通过）复核一遍。

#### 指标 D：成本与延迟

单张成本（含免费额度的折算）、P95 延迟、整体运行时长。

> 样本量提醒：单轮 198 张、5% 阈值对应最多 9 张未通过，统计余量不大。报告必须给**逐轮数值 + 置信区间**，不能只报一个"平均 3%"。

### 6.5 检测器有效性门禁（防止"假达标"）

每个检测器进入主口径前必须过门禁（与原图指标 A 对应）：

| 门禁项 | 阈值（R-3 确认） | 不通过的处理 |
| --- | --- | --- |
| AI 原图漏检率 `A_ai` | ≤ 30%（检出率 ≥ 70%） | 该检测器**不纳入主口径**，仅作参考 |
| 实拍原图误报率 `A_real` | ≤ 5% | 同上 |
| uncertain 率 | ≤ 5% | 按最坏情况复核 |
| 技术失败率 | ≤ 2% | 该轮重跑 |
| 结果完整性 | 198 × 4（792）全部有记录 | 补齐后重算 |

### 6.6 反指标（出现即判测试无效）

- 为提分而更换更宽松的提示词或阈值；
- 只报通过的轮次、删除失败样本、只报最好的一轮；
- 用"永远判 physical"的退化解；
- 把 uncertain 藏起来不提，或把技术失败曲解为通过；
- 只测 AI 图、不测实拍图（无法发现误报）；
- 拿处理图当原图基准，或用不同批次的原图对比；
- 事后修改 `manifest.csv` 的标签或分母。
