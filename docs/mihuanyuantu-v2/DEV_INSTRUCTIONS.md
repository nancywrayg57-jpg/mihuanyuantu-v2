# 蜜獾原图 v2 · Agent 开发指令

面向 Cursor / 编码 Agent。本文只做**切片编排**与**依据路径**索引；不发明产品需求，不替代现行合同正文。

## 1. 权威顺序

1. **产品行为** → `docs/蜜獾原图-v2-PRD-v2.0.md`（最高）
2. **落地结构 / 模块 / 数据 / 部署形态** → `docs/蜜獾原图-v2-项目架构-v1.0.md`
3. **切片编排与路径** → 本文件  

冲突时：红线与用户可见行为听 PRD；目录、表、适配器、进程与部署结构听架构；本文件不得新增 PRD/架构未有之需求。若发现三者无法同时满足，**停止实现并在聊天中提问**，禁止自行定夺。

## 2. 执行身份与过程账本

- 主执行者：编码 Agent。
- 必须同时遵循：`aidevops/SKILL.md`。
- 仓库根职责文件（与本指令配合，须阅读并在变更后维护）：
  - `AGENTS.md` — 协作宪法与工作纪律
  - `handoff.md` — 新会话一分钟接手
  - `anchor.md` — 现行约束锚点
  - `checkpoint.md` — 可核实状态检查点
- 新会话顺序：`handoff.md` → `anchor.md` → `checkpoint.md` → 本文件 → `docs/mihuanyuantu-v2/progress.yaml`。
- 每完成一切片或关键闸口，更新：
  - `docs/mihuanyuantu-v2/progress.yaml`
  - 对应阶段文件：`00-discovery.yaml` / `01-design.yaml` / `02-delivery.yaml` / `03-acceptance.yaml`
  - `docs/mihuanyuantu-v2/wiki.md`（只记可复用规则、命令、风险与交接，不写流水账叙事）
  - 仓库根 `checkpoint.md`、`handoff.md`（状态与下一步）；约束变更时同步 `anchor.md`
- 仓库级路由：`.aidevops-active.yaml`；协作纪律见 `AGENTS.md`。

## 3. 硬性禁止

- 禁止把 HTML 原型的 mock / localStorage 当作后端已验收证据。
- 禁止在未满足生产门禁时，对公网生产环境开放收费或对外宣称「检测通过」。
- 禁止生成 ZIP 交付包；禁止独立 GPS 选择页；禁止生图自动进入硬件化交付（生图只入库，处理另提交）——细则见 PRD。
- 禁止提交密钥、口令、真实 `.env`、私钥；禁止把密钥写入本指令、PRD、架构、wiki 或提交记录。
- 禁止将 `docs/architecture_decisions/`、`docs/archive/`、`docs/蜜獾原图-v2-待决策清单-v1.0.md` 列为开发依据或从其正文拷贝规则到实现说明。
- 禁止整包迁入旧版伪队列、假页面、用户数据、积分与 Key。
- 禁止在 `main` 上直接开发。

## 10. 切片编排

原则：

- **基础能力先就绪**，再开启可并行切片。
- **允许有限并行**：在不破坏 PRD 行为与架构边界的前提下，真五层、真 Gemini、生图等可并行推进。
- **有依赖则不可抢跑**（见下表「依赖」列）。
- 每切片退出必须有可重复验证证据，并回写 AidevOps 阶段文件。

### 10.1 第一刀（S1）实现边界（编排级）

- 账本 / 任务状态机 / 落库 worker / LocalDisk 网关下载：真实实现。
- 预审：桩（默认通过；管理员可强制拒绝）；文件硬校验必须真。
- 五层：假桩，但交付物合同字段必须真（可下载 `.jpg`、快照、报告结构键名对齐检测合同）。
- 最终检测：规则夹具，键名与通过规则对齐 `docs/蜜獾原图-v2-Gemini-Vision检测与自动重做方案-v1.0.md`。
- 不做：自动重做、主动重处理、2–10 批次、生图、URL 真导入、405 运营台、真预审冻号台、OSS 必选、ZIP。

### 10.2 资金与角色（编排级）

- 积分：**租户共用**整数户；扣费/冻结记操作账号；账号预审冻结不冻结整户余额。
- 订单客服 A 档：确认/拒单与查看订单凭证；不解冻、不看业务原图、不改系统模型/预设。
- 技术客服：归入 S6，不作为 S1 退出必验。

## 11. 生产门禁与部署

在同时满足前，**禁止**生产环境收费与对外「检测通过」服务承诺：

- PRD 要求的真实模型/算法小样与归档证据已具备（含最终检测与真五层相关要求）。
- `docs/蜜獾原图-v2-生产物料清单-v1.0.md` 中生产就绪阻塞项已关闭或由管理员明确接受残余风险。
- 部署目标、域名、TLS、回滚与监控按架构与物料执行。

Agent 可在门禁通过后协助执行部署；缺密钥或 SSH 时在聊天中向管理员索取。不得绕过门禁强行发布。

## 12. 切片完成定义（通用）

每一切片标记完成前，须同时具备：

1. 代码在功能分支上可审查；
2. 对照 PRD 相关 FR/AC（及本切片范围）的验证记录或命令输出；
3. `docs/mihuanyuantu-v2/progress.yaml` 与相关阶段文件已更新；
4. 无密钥泄漏；
5. 未把夹具/桩误标为生产已验收。

## 13. 开工检查清单（每次会话）

1. 阅读仓库根 `handoff.md`、`anchor.md`、`checkpoint.md`、`AGENTS.md`，再读本文件与 `aidevops/SKILL.md`。  
2. 阅读现行 PRD、架构、物料清单、Gemini 方案中与本切片相关的章节。  
3. 需要 UI 时对照 `prototype/`。  
4. 查看 `docs/mihuanyuantu-v2/progress.yaml` 当前切片与阻塞。  
5. 在 `cursor/<功能简述>-9973` 分支工作。  
6. 缺密钥则先问管理员，再写本机配置。  
7. 实现后跑本切片验证，并更新 AidevOps 账本与根目录 `checkpoint.md` / `handoff.md`（必要时 `anchor.md`）。
