## 10. 阶段划分

原则：

- **基础能力先就绪**，再开启可并行阶段。
- **允许有限并行**：在不破坏 PRD 行为与架构边界的前提下，真实五层处理、真 Gemini、生图等可并行推进。
- **有依赖则不可抢跑**。
- **S0–S6 自主推进**；**S7 须管理员确认**。
- 每阶段退出必须有可重复验证证据，并回写 AidevOps 与 `checkpoint.md` §0。
- **清单硬规则**：每个阶段开工前，本文件须已写明该阶段的 `tasks` / `exit_evidence` / `forbidden`（任务 / 退出证据 / 禁止项）。当前 **S0、S1、S2、S3** 已齐；**开 S4–S7 任一阶段前必须先补齐该阶段清单，缺一禁止开工**。清单正文以本文件为准；`progress.yaml` / `02-delivery.yaml` 只镜像完成状态与 `next_action`。条目只写 ID 与短句，行为冲突仍听 PRD。

## 12. 阶段完成定义（通用）

1. 代码在功能分支上可审查；
2. 对照 PRD 相关 FR/AC（及本阶段范围）的验证记录或命令输出；
3. **本里程碑端到端测试已通过**（主验证环境；覆盖用户可见主路径；有可复查证据）；未通过则不得标完成、不得开下一阶段；
4. `progress.yaml` 与相关阶段文件已更新（含端测结果指针）；
5. `checkpoint.md` §0 已更新（含 SHA/分支、验证态与端测证据路径）；
6. 无密钥泄漏；
7. 未把规则替身/占位实现误标为生产已验收；未把单元测试误标为端测通过。
