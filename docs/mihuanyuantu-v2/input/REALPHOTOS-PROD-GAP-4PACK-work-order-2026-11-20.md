## W1 · 资源 URL 导入未作为正式可用能力打开

### 更新项

| 子项 | 说明 |
| --- | --- |
| W1-a 合同启用 | 管理端将 `duty=import` 供应商合同设为**启用**，Base URL 指向**正式**导入服务（非临时 `127.0.0.1` 测完即关） |
| W1-b 对象级验收 | 用真实样例 URL 完成至少 1 次对象级导入入库（关 S7 **R4**） |
| W1-c 产品口径 | 导入页/帮助文案标明：正式可用；失败时区分「未配置 / 供应商错 / 条目非法」 |
| W1-d 证据 | 写入 closeout：合同状态、样例 URL 形态（可脱敏）、`imported≥1`、asset id、`formalSupplier` 字段若有 |

### 如何更新

1. **先物料**：管理员确认正式导入 Base URL + 至少 1 个可公开测的样例对象路径（见下「额外物料」）。  
2. 代码侧核对已有能力：`RealphotosGrowthService.import_resources`、`import_fetch.py`、API 型路径（历史 #67）；**优先配置启用，少改代码**。  
3. 若正式供应商鉴权/路径与现实现不符：最小适配 `import` duty 的 URL 拼装与错误码，禁止顺手改其它 duty。  
4. 管理员在生产（或等同配置的预发）启用合同 → 商家账号跑通「每行 URL」与「JSON」各至少 1 次。  
5. 测完**不要**再把正式渠道改回停用（除非验收失败回滚）。

### 是否需要额外物料

| 物料 | 谁提供 | 用途 |
| --- | --- | --- |
| 正式导入 Base URL | 管理员 | 写入/核对 `duty=import` 合同 |
| 样例对象完整 URL 或「基址+路径」规则 + 1 张可拉图片 | 管理员/供应商 | 对象级验收（R4） |
| 若供应商要 Token/Header | 管理员写入生产保密目录 duty secrets | **禁止入库**；`import` 历史上可无 secret，以现行实现为准 |
| 测试商家账号 | 已有种子号可先用；正式对外前仍建议改口令（R6，本包不强制） | 端测 |

**无物料则 W1 只能做代码/文案预备，不得标「生产正式可用」。**

### 预期更新结果

- 生产 `duty=import`：**启用**且 Base URL 为正式地址。  
- 商家 URL 导入主路径可用；`SERVICE_NOT_CONFIGURED` 不再是默认常态。  
- 证据包可关 R4；对外可说「支持 URL/JSON 导入」（仍受供应商可用性约束）。  
- `production_billing` 仍为 false。

## W3 · 单 worker 顺序处理导致大批次等待长

### 更新项（分两档，避免一次上高风险并发）

| 档 | 子项 | 说明 |
| --- | --- | --- |
| **A 必做（产品可见性）** | W3-A1 | 任务列表/详情展示队列位置或「前方约 N 单 / 预计等待」类信息（有数据则显示，无则诚实空态） |
| A | W3-A2 | 批量提交成功后的提示：说明当前为顺序处理、单张约 1.5–3 分钟量级（以现行生产实测为口径，可配置文案常量） |
| A | W3-A3 | 帮助/FAQ 补充大批次等待说明（若已有帮助菜单） |
| **B 可选（吞吐）** | W3-B1 | 评估并实现受控并发：多 `process` worker 或单进程内有限并行；**必须**保持按张积分冻结/结算/释放正确 |
| B | W3-B2 | 同机资源门槛：CPU/内存/Gemini 限流；给默认并发上限与运维开关 |
| B | W3-B3 | 开发机 + 生产抽检：20～50 张批次总时长对比证据 |

**建议默认交付 A；B 须管理员显式点名开工**（同机 PG+单机风险 R1）。

### 如何更新

**A**

1. 查任务/队列查询 API 是否已有排队元数据；没有则最小增加「同租户/全局 submitted 计数」只读字段。  
2. 前端任务页/批量成功 Toast 展示等待说明。  
3. 证据：截图 + 文案；不要求缩短真实墙钟时间。

**B（仅授权后）**

1. 读架构 §6 / 现有 `realphotos-process` systemd 与 job claim 逻辑，设计「多实例 claim 不双消费」。  
2. 开发机压测积分对账 → 再生产灰度（例如并发 2）。  
3. 回滚：并发改回 1 / 停多余 unit。

### 是否需要额外物料

| 档 | 物料 |
| --- | --- |
| A | **否** |
| B | 管理员确认可接受的并发上限；生产机资源余量知情（不写 IP 进口令）；可选：单独压测窗口 |

### 预期更新结果

- **A**：商家知道「要等多久/为何慢」，催单下降；墙钟时间可仍约 50 张 ~70 分钟。  
- **B**（若做）：同样 50 张墙钟明显下降，且积分流水按张正确；有对比日志。

## W4 · 检测/处理默认策略对运营不够直观

### 更新项

| 子项 | 说明 |
| --- | --- |
| W4-a 策略摘要卡 | 管理端（建议 `provider-contracts` 页或运营指标旁）只读展示：最终检测 duty 的 provider/modelId/enabled/configVersion；关键处理默认（若代码有模块常量/配置可读则展示，无则显式写「见服务端默认，本页不虚构」） |
| W4-b 最近抽样概况 | 可选：最近 N 条含检测报告的任务通过/未通过计数（仅管理员）；无数据则空态 |

### 如何更新

1. 复用已有合同 API（历史已支持改 `final_detection` modelId）。  
2. 前端增强只读摘要 + 链接到修改对话框；不做客户自建 Key。  
3. 若拉「最近抽样」：用现有任务/报告查询，注意租户隔离与权限（仅 admin）。  
4. 手测：管理员打开即可口述「当前检测模型是什么、如何改回去」。

### 是否需要额外物料

**否**（只读展示 + 文案）。若要展示「最近通过率」，需生产上已有足够任务数据（一般已有）。

### 预期更新结果

- 管理员/运营 30 秒内能说清当前最终检测默认模型与是否启用。  
- 调参与客服话术一致；不引入错误的「已达标/已收费」表述。
