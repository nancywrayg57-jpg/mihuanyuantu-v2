## 二、P0

### UXA-001 商家可进入平台演示页，页面直接展示权限码与“租户套餐”伪 CRUD

- 角色/页面：商家 `rp_merchant_a1`；`/permission/page`、`/permission/button`、`/system/dict`、`/tenant/package/index`、`/schedule`
- 现象：
  - 商家侧边栏在首屏会短暂出现「日程 / 页面权限 / 按钮权限 / 字典管理 / 租户套餐」演示分组（截图 `screens/merchant-library.png`、`screens/merchant-workspace.png`）。
  - 即使分组消失，商家直接访问上述 URL 仍可打开页面；`/permission/button` 明文列出 `realphotos:gateway:read`、`realphotos:jobs:enqueue`、`realphotos:jobs:read`、`realphotos:wallet:read`、`realphotos:workspace:read`；`/tenant/package/index` 展示「新建套餐 / 编辑 / 删除」的伪 CRUD（页面自述“数据仅保存在当前浏览器内”）。
- 证据：
  - `screens/demo-permission-button.png`
  - `screens/demo-tenant-package.png`
  - `screens/merchant-library.png`（侧栏演示分组）
- 根因：
  - `app-layout.tsx` 的 `hideDemoMenus` 默认 `false`，要等 `/api/v1/realphotos/me` 返回后才会隐藏演示分组；首屏存在可见窗口。
  - 演示路由没有针对业务角色的统一路由守卫；菜单隐藏不等于 URL 禁止访问。
- 影响：商家会误以为平台有未开放的日程/权限/套餐管理能力；裸权限码和伪 CRUD 严重损害商用可信度，也是权限边界风险。
- 建议：
  1. 对业务角色（`rp_merchant*` / `rp_tech_support` / `rp_order_support` / `rp_admin`）默认隐藏演示分组，不再等 `/me`。
  2. 对 `/schedule`、`/permission/*`、`/system/dict`、`/tenant/package/*` 增加角色守卫：业务角色访问时返回 404/重定向到工作台，而不是渲染演示页。
  3. 保留演示页仅给平台内部演示账号/环境，并在页面显式标注演示环境。
- 需确认：演示页是否仍需保留给内部演示；若保留，需指定允许访问的角色/环境。
