## 1. 总体系统架构

### 1.1 逻辑架构（文字同构）

```text
┌──────────── Browser (Next.js / React realphotos UI) ────────────┐
│ 商家 / 订单客服 / 技术客服 / 管理员 · 角色裁剪菜单 · 任务/图库/运营台 │
└────────────────────────── HTTPS ────────────────────────────────┘
                              │
                     Nginx + TLS 反向代理
                              │
┌──────────── FastAPI (aojuai + capability: realphotos) ──────────┐
│ 会话登录 / 租户 / RBAC │ 整数积分流水 │ 任务/批次/检测 │ 生图入库     │
│ 业务 API (X-API-Key)   │ 受控图片网关 │ 运营台 / 预设 / 工单 / 日志   │
│ 供应商合同（按职责 duty）│ OpenAPI                                     │
└───────┬───────────────────────────────┬─────────────────────────┘
        │                               │
   PostgreSQL 持久库              LocalDisk（受控网关读；禁止裸路径）
   任务队列 + 账本 + 业务表        upload / phy-export / export …
        │
   独立进程：process worker / notify / cleanup
        │
   模型适配器（按职责）：预审 · 生图 · 文本优化 · Gemini 检测 · URL 导入 …
```

**部署形态（已合入事实）**：Linux + systemd 多单元（api / web / process / notify / cleanup）+ Nginx 切流；经济起步同机 PostgreSQL（单点风险已书面接受）。出口可达性依赖受控代理链路（有到期风险，见《01》第 7 章）。

**质量门禁**：GitHub PR → CI gate（密钥扫描 / 后端 / 前端 / 文档）→ 非作者审合；里程碑另需指定环境端测证据。

## 2. 核心子系统架构详述

### 2.1 前端与角色信息架构

- **技术**：Next.js / React / TypeScript（`aojuai-main/frontend`），业务页集中在 `realphotos/*`。  
- **角色**：商家、订单客服（A 档）、技术客服、平台管理员；菜单按角色裁剪；管理员工作台不套商家四卡（PRD/阶段清单）。  
- **主路径（商家）**：登录 → 工作台/上传 → 选启用预设 → 单张或批次处理 → 任务详情/下载（过期拒绝）→ 站内消息。  
- **返工热点（前端）**：任务页、图库、工作台、预设页触碰次数靠前（见 `evidence_metrics.json` hot files）。

### 2.2 租户、RBAC 与积分

- **租户隔离**：同租户账号可共享积分池；跨租户拒绝。  
- **积分**：整数流水；图片处理提交前按张冻结；检测通过消费、未通过/前置失败释放等路径分列；技术失败可保持 `held_until_tech_support` 至客服审计（以 PRD/阶段已记录决定为准）。  
- **生图**：不预冻、成功入库后按张扣（S5）；与处理链路计费语义分离。

### 2.3 图片处理、五层与检测

```text
上传硬校验 →（预审，S6 真模型路径）→ 入队
    → L1…L5 五层处理（S2 起非 placeholder）
    → 最终检测（S1 替身 → S3 真 Gemini）
    → 可选自动重做 / 主动重处理（合同边界内）
    → 网关下载 + expires_at
```

- **话术铁律**：替身 ≠ 真 Gemini ≠ 对外「检测通过」≠ 收费开放。  
- **调参章**：止血 / 试点 / 受控默认强度调整必须写清「未默认晋升」边界（《01》第 6 章）。

### 2.4 增长能力与对外 API

- **生图入库**：可先无真供应商跑通产品形态（#23）。  
- **URL 导入**：含 API 型供应商配置（#67 等）。  
- **客户业务 API**：`X-API-Key` + scope=`image_processing` + OpenAPI（FR-033，S5）。  
- **模型通道**：按职责可配置（预审/生图/检测/导入），平台托管；**客户自建上游 Key** 不在现行合同建议范围。

### 2.5 运营完备（S6）

- 真预审、锁图/冻号、技术客服解冻与申诉。  
- 用户/租户管理、系统日志（账号变更类）。  
- 设备预设运营（405 量级导入/启停；处理页只见启用项）。  
- 管理员运营指标；供应商密钥/合同 UX。

### 2.6 安全与受控访问

- 会话登录；验证码/注册路径按合入实现。  
- 图片经受控网关，响应不暴露裸磁盘路径。  
- 密钥不入库；CI `secret_scan`；生产配置权限收敛。  
- 生产后安全加固合入（#89）与 UX 迭代并行。

### 3.2 下一阶段（仅合同内）

| 波次 | 主题 | 说明 |
| --- | --- | --- |
| 近 | 运维硬化 | 出口代理自有化替换临期第三方；备份/告警规程；种子口令轮换 |
| 近 | 质量门禁 | 端测分层（冒烟 / 核心域 / 夜间全量）；显示层回归（勿只信 API） |
| 中 | 体验与数据诚实 | 预设变体/去重治理巩固；任务/流水/文案语义一致性 |
| 中 | 检测与算法 | 在「未擅自默认晋升」门禁下继续合同内调参与证据归档 |

**明确不在本路线图宣称的**：生产收费已开放、ZIP 交付、独立 GPS 选择页、生图成功后自动进入相机参数处理、客户自建上游模型 Key、外部发布包装等 PRD 禁止或未授权项。
