# 模块复用评估

依据当前架构第 3.2 节逐项提取，并补充其直接关联的字段回显、字典、旧版 EXIF 实现和测试。保留 TypeScript 来源材料；没有把旧 Node 后端移入 v2，也没有生成伪称可运行的 Python 实现。

## 1. 分类与迁移目标

| 编号 | 来源快照 | 可提取部分 | 复用条件及目标 |
|---|---|---|---|
| RM-001 | [presetSerializer.ts](../01_源码参考/原样快照/server/presetSerializer.ts) | snake_case / camelCase 别名、GPS / MakerNote 防丢映射 | 映射逻辑参考；按新 SQLAlchemy / Pydantic 字段生成 DTO。去除 owner、旧归属及运行统计直传，不能继续 `...row` 暴露整行 |
| RM-002 | [presetEchoFields.ts](../01_源码参考/原样快照/client/src/lib/presetEchoFields.ts) | nullish 回退、编辑回显、未改动即保留的纯函数 | 语义可复用；使用新生成类型及受控输入校验，不复制旧页面状态管理。显式区分缺省、空字符串、null 与数值 0 |
| RM-003 | [domain-dictionaries.ts](../01_源码参考/原样快照/shared/domain-dictionaries.ts) | 摄影字段的分类和值字典 | 本包仅将 PARAMETER_* 自动提为设备字典；原文件其他业务字典是历史参考。v2 分类可扩展，不能把四类硬编码为设备总范围 |

| RM-005 | [frequencyProcessor.ts](../01_源码参考/原样快照/server/frequencyProcessor.ts) | FFT / IFFT、逐行亮度扰动、低频保护思路 | 旧代码是逐行一维处理，不是已验证的全图二维 FFT。校验补零、裁回、灰度 / RGBA、共轭与数值边界；迁移到 NumPy / SciPy，注入可重现随机源 |
| RM-006 | [fingerprintDestroyer.ts](../01_源码参考/原样快照/server/fingerprintDestroyer.ts) | 局部细微像素扰动、可单独验证的噪声思路 | 仅提取不改变内容 / 尺寸的部分；禁用旧旋转、裁切、缩放还原、可见调色总入口。不能承诺破坏所有指纹或保证检测通过 |

| RM-008 | [exifWriter.ts](../01_源码参考/原样快照/server/exifWriter.ts) | 45 项机型规格、APEX 公式参考、旧 MakerNote 品牌分支 | 仅作补充 / 差异参考，不用旧 piexifjs 替代 v2 ExifTool；手工构造的最小 MakerNote 不能当成真实厂商文件、可用模板或核验通过 |
| RM-009 | [exifVerifier.ts](../01_源码参考/原样快照/server/exifVerifier.ts) | 五维检测键、提示词、响应解析参考 | 这是模型视觉评分模块，**不是 EXIF 文件回读器**。只提取合同语义；去除旧数据库 Key / 供应商轮询、静默零分和自动付费重试。真实接口与返回 Schema 按 v2 适配 |
| RM-010 | [uploadSimulator.ts](../01_源码参考/原样快照/server/uploadSimulator.ts) | JPEG 质量、色度采样、重编码顺序的参考字段 | 迁移为通用电商编码配置。删除旧平台选择、最大尺寸缩放、色彩偏移；最终编码后再做元数据 / 字节 / 尺寸验收 |
| RM-011 | [sizeOptimizer.ts](../01_源码参考/原样快照/server/sizeOptimizer.ts) | `finalize` 后测真实 Buffer 字节、迭代控制点 | 仅保留控制模式；旧 60%–80% 目标、质量下限与成功判定不能使用。v2 要求最终实际字节不少于五层输入字节；达不到即明确失败 |

## 2. 已读到的具体风险

| 来源定位 | 实际行为 | 处理要求 |
|---|---|---|
| imagePhysicalizer.ts:247–264 | composite 结果在 `.then()` 中丢弃，转而将原图饱和度乘 1.02 | 禁止当作已实现的正确色差模块搬用 |
| imagePhysicalizer.ts:363–373 | 像素总入口内部先做频域处理 | 拆开后按 v2 像素→频域→指纹→EXIF→通用编码运行 |
| imagePhysicalizer.ts:407–409 等 | 异常时返回原图，日志仍可能被上层当作完成 | 分层错误必须可观察并进入真实失败路径 |
| fingerprintDestroyer.ts:227–251、275–313 | 调整色调、饱和度、亮度，旋转 / 裁切后 resize 回原尺寸 | 禁用对应流程，不能因最终尺寸相同就认为内容未变 |
| exifToolWriter.ts:394–422 | ShutterSpeedValue 直接复用快门串，ApertureValue / MaxApertureValue 直接复用光圈数值 | 物理值与 APEX 语义分开；至少覆盖 Tv=-log2(t)、Av=2log2(N)，并验证 ExifTool 实际输入 / 回读表示，不能仅做字符串对照 |
| exifToolWriter.ts:220–263、385–417 | ISO、光圈、焦距会被强制吸附到标准档位 | 手机 6.765mm、f/1.78 等设备参数不能因“标准化”被改成另一个物理值；按机型约束验证 |
| exifToolWriter.ts:66、503–523 | 接口声明 maker_note_template，但无实际消费该字段的逻辑；写入带 `-m`，异常返回原图 | 模板名称存在不代表已写入 MakerNote；移除静默成功，按所需标签回读并登记真实能力 |
| exifToolWriter.ts:490–529 | 创建缩略图临时文件，finally 只清理 input/output | Python 实现覆盖缩略图在内的全部临时文件生命周期，不继承遗漏 |
| exifWriter.ts:267–665 | 按品牌构造最小 MakerNote；部分品牌仅拼接前缀与空 IFD | 保留为未验证的历史实现，不称为真实厂商 MakerNote 样本 |
| exifVerifier.ts:84–149、354 起 | 模型提示词和解析 / 调用逻辑 | 实现独立的文件元数据读回与最终 Gemini 检测；异常不得生成伪造低分报告 |
| uploadSimulator.ts:80 起、270 起 | 按平台配置重编码、尺寸 / 色彩处理 | 来源声明“实测”尚无本轮样本证据；参数仅参考，不是平台规范 |
| sizeOptimizer.ts:80–88、104 起 | 默认目标 0.6–0.8，主流程按旧体积带收敛 | 必须重写为 v2 字节下限验收，不可把历史测试通过当作新规则通过 |

来源快照行号保持原样；表内行号是对旧源码的定位，不是对本评估的行号。完整 tag 赋值和表达式已保存为 [JSON](../02_设备参数/EXIF标签映射.json)。

## 3. 已提取的测试如何使用

10 个相关测试文件按旧路径保存：序列化、GPS / MakerNote 回显、指纹、EXIF、模型 Key 类型边界、摄影参数标准化、尺寸、平台编码及类别 / 导入测试。它们用于识别边界案例；本轮没有运行。

其中尺寸 60%–80%、几何扰动、标准档位吸附或旧模型路由的断言可能正是 v2 要淘汰的行为，不能整套照搬。旧测试依赖 sharp、ExifTool、vitest、数据库或模型模块的 mock；快照没有补齐全部运行依赖，不是一个独立可启动工程。

离线提取 / 数据完整性校验与图片算法测试分开记录，后者为 NOT_RUN。[未经本地验证]

## 4. 后续实施顺序

1. 先落新字段契约、别名规则与版本化设备 JSON；逐条核对候选，清理旧归属与运行值。
2. 用固定 JPEG / PNG、灰度 / RGBA、EXIF 方向、宽高非 2 的幂等边界样本实现独立像素、频域和受限指纹层。
3. 实现严格 EXIF 写入 / 读回；验证 APEX、实际尺寸、时间、GPS、FocalPlane 单位及真实 MakerNote 能力。
4. 最终通用编码后验证尺寸、sRGB JPEG、实际字节下限与元数据；不满足时失败。
5. 单独实现 Gemini 返回合同与计费失败规则，最后再接入 v2 任务状态机、租户和整数账本。
